# Frontier AI Harness

Use this skill when the user wants stronger reasoning, better debugging,
architecture-aware fixes, or peak output from frontier models.

## Core Principle

The same model can vary 10x in effective output quality depending on process,
routing, and prompt structure. Optimize the harness, not just the model ID.

## When to Use

- Fix errors with full project understanding before patching
- Require proof-before-action reasoning
- Choose the right frontier model for the task
- Maximize output quality from any available model

## Component Skills

| Goal | Use This Skill |
|---|---|
| Understand architecture before fixing | `architecture-led-fix` |
| Strict first-principles reasoning | `strict-reasoning` |
| Select the right frontier model | `frontier-model-routing` |
| Optimize prompts for any model | `max-model-performance` |
| Root-cause debugging loop | `systematic-debugging` |

## Procedure

1. Identify whether the task needs architecture understanding, strict reasoning, model selection, or prompt optimization.
2. Load the matching component skill first.
3. Apply that skill's process before any action.
4. If multiple skills apply, stack them in this order:
   - `architecture-led-fix` for codebase errors
   - `strict-reasoning` for analysis or planning
   - `frontier-model-routing` to pick the model
   - `max-model-performance` to format the prompt
   - `systematic-debugging` to validate the fix

## Verification

- Correct component skill was selected and applied.
- Process rules from that skill were followed before action.
- Output reflects the harness, not just raw model behavior.
- Adjacent behavior unchanged.
